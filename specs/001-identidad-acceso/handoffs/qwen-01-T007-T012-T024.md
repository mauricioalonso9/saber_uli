## Reglas de siempre

- Prueba primero: escríbela, confirma que falla y haz commit; luego implementa.
- Un commit por tarea, en Conventional Commits y en español, por ejemplo
  `test(infra): prueba de contenedores (T007)` o `build(infra): compose y perfiles (T012)`.
- Al terminar cada tarea, agrega bajo ella en `tasks.md` la línea
  `- Estado: lista para revisión. …` con un resumen breve de lo hecho y de las desviaciones.
  **No marques la casilla.**
- No cambies `contracts/openapi.yaml`, `data-model.md`, los ADR ni lo que ya hizo Opus en
  `infra/nginx/` e `infra/postgres/init/`. Si algo no encaja, escribe
  `- Decisión pendiente: …` bajo la tarea y sigue.
- Nunca subas un `.env` ni secretos reales. Las contraseñas de prueba se generan al vuelo.
- Docker 29 y Compose v5 están instalados en esta máquina; `actionlint` no (usa su imagen).
- En Windows, ejecuta `lint-imports` con `PYTHONIOENCODING=utf-8` (ver la nota de T003).

## T007 — `backend/tests/infra/test_containers.py`

**Objetivo**: verificar desde pytest que la infraestructura cumple los principios IV y X.

Restricciones:

- Sin dependencias nuevas. Usa la CLI de Docker con `subprocess.run([...], check=False,
  capture_output=True, text=True)` (argumentos en lista, nunca `shell=True`). Para las cabeceras
  HTTP usa `httpx`, que ya es dependencia, en lugar de `curl`.
- Marca todo el módulo con `pytestmark = pytest.mark.infra` (registra el marcador en
  `pyproject.toml`) y omítelo con `skipif` si `docker info` falla, **salvo** que
  `REQUIRE_DOCKER=1`: en ese caso la prueba debe fallar con un mensaje claro.
- Usa un nombre de proyecto propio (`-p saber-uli-infra-test`) para no tocar el stack de
  desarrollo, y `docker compose ... down -v --remove-orphans` en el teardown de la fixture.
- Las contraseñas y secretos se generan en una fixture con `secrets.token_urlsafe(32)` y se
  escriben en un archivo de entorno temporal (`tmp_path_factory`) que se pasa con `--env-file`.
  Toma la lista de variables de `.env.example` (T013) para no duplicarla.
- La URL del proxy se lee de `SABER_PROXY_URL` con valor por defecto `http://localhost`.

Una función de prueba por comprobación, para que el informe diga exactamente qué falta:

| Prueba | Qué comprueba |
|--------|---------------|
| `test_compose_config_es_valido` | `docker compose -f compose.yaml [-f compose.override.yaml \| -f compose.prod.yaml] config -q` sale con 0 en las tres combinaciones (base, base + override, base + prod) |
| `test_imagen_backend_corre_con_uid_10001` | `docker run --rm --entrypoint id <imagen api> -u` imprime `10001` |
| `test_servicios_healthy_y_migrate_exitoso` | `up -d --wait` sale con 0; `ps -a --format json`: todos los servicios de larga vida `healthy` y `migrate` con `ExitCode` 0 |
| `test_cabeceras_de_seguridad_del_proxy` | `GET /` incluye `Content-Security-Policy` (sin `unsafe-inline` en `script-src`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` y `X-Frame-Options: DENY` |
| `test_service_worker_allowed` | `GET /sw.js` incluye `Service-Worker-Allowed: /` y `Cache-Control: no-cache` |

Si en Windows `docker run -v` necesita la ruta del repositorio en un formato particular, resuélvelo

## T012 — `compose.yaml`, `compose.override.yaml`, `compose.prod.yaml`

**Servicios** (tabla de plan.md):

| Servicio | Imagen o build | Health check sugerido |
|----------|----------------|-----------------------|
| `proxy` | `frontend/Dockerfile` (nginx-unprivileged, puerto interno 8080) | `curl -fsS http://localhost:8080/` (o `wget -q --spider` si la imagen es alpine) |
| `api` | `backend/Dockerfile`, comando api | `python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/health')"` (la imagen slim no trae curl) |
| `worker` | `backend/Dockerfile`, comando worker | `celery -A saber_uli.worker inspect ping -d celery@$$HOSTNAME` |
| `beat` | `backend/Dockerfile`, comando beat | `find /tmp/beat-heartbeat -mmin -2 \| grep -q .` |
| `migrate` | `backend/Dockerfile`, comando migrate; `restart: "no"` | código de salida |
| `db` | `postgres:18`; volumen en `/var/lib/postgresql` (no en `/var/lib/postgresql/data`: cambió en PG 18); monta `infra/postgres/init/` en `/docker-entrypoint-initdb.d:ro`; `command: postgres -c shared_preload_libraries=pg_stat_statements` | `pg_isready -U postgres -d $${POSTGRES_DB}` |
| `redis` | `redis:8-alpine` | `redis-cli ping` |
| `mailpit` | `axllent/mailpit`, con `user:` explícito sin privilegios; solo en override y perfil `e2e` | `["CMD", "/mailpit", "readyz"]` |
| `oidc` | `ghcr.io/navikt/mock-oauth2-server`, con `user:` explícito; solo en el perfil `e2e` | ver el riesgo de abajo |

**Dependencias**: `api`, `worker` y `beat` dependen de `migrate` con
`condition: service_completed_successfully`, y `migrate` depende de `db` y `redis` con
`service_healthy`. `proxy` **no** depende de `api`: Nginx resuelve `api` en tiempo de ejecución
(`resolver 127.0.0.11` en `infra/nginx/locations.conf`), así que puede arrancar solo.

**Credenciales por rol** (R-07): `migrate` usa `saber_migrator` (`MIGRATION_DATABASE_URL`); `api`,
`worker` y `beat` usan `saber_app` (`DATABASE_URL`). Nunca el superusuario. Compose arma ambas URL
con `postgresql+asyncpg://` a partir de las contraseñas del `.env`. Las contraseñas vienen del `.env` (`SABER_MIGRATOR_PASSWORD`,
`SABER_APP_PASSWORD`, `SABER_BI_PASSWORD`, `POSTGRES_PASSWORD`) y **no** llevan valores por
defecto en Compose: si falta alguna, usa la sintaxis `${VAR:?mensaje}` para que Compose falle con
un mensaje claro.

**Override (desarrollo)**: recarga en caliente de `api` (montaje de `backend/src` y
`uvicorn --reload`), `mailpit`, y puertos solo en `127.0.0.1`: proxy `127.0.0.1:80:8080`
(`vite.config.ts` ya redirige `/api` a `localhost:80`), db `5432`, mailpit `8025`.

**Prod**: monta `infra/nginx/tls.conf` sobre `/etc/nginx/conf.d/default.conf` y los certificados
desde `infra/docker/certs/` (ya está en `.dockerignore`); publica 443 y 80; sin `mailpit`;
`restart: unless-stopped`.

**Perfil `e2e`**: `oidc` y `mailpit`. Crea `infra/docker/mock-oauth2.json` con dos emisores:

- inquilino válido: `issuerId` = `11111111-1111-4111-8111-111111111111`
  (`ENTRA_TENANT_ID` de e2e), con `tid` igual a ese valor;
- externo: `issuerId` = `22222222-2222-4222-8222-222222222222`, con `tid` igual a ese valor.

Cada uno emite `oid`, `tid`, `name`, `email` y `preferred_username` de prueba, con
`interactiveLogin` activo para que Playwright (T069) elija el usuario. Documenta los dos GUID en
`.env.example`.

**Riesgo que debes verificar, no suponer**: la imagen de `mock-oauth2-server` podría no traer
shell ni herramientas HTTP (imagen *distroless*). Revisa con `docker run --rm --entrypoint sh ...`
o inspeccionando la imagen. Si no hay forma de ejecutar un health check dentro del contenedor,
usa `condition: service_started` para quien dependa de `oidc` y registra
`- Decisión pendiente: health check de oidc …` bajo T012. No agregues herramientas a la imagen.

**Verificación en dos tiempos** (nota de Opus en `tasks.md`):

- **Al entregar T012**:
  - `test_compose_config_es_valido` en verde.
  - `db`, `redis`, `proxy`, `mailpit` y `oidc` quedan `healthy`.
  - `test_cabeceras_de_seguridad_del_proxy`, `test_service_worker_allowed`,
    `test_roles_y_extensiones_de_postgres` y `test_ningun_proceso_principal_con_uid_0` pasan sobre

  - `api`, `worker`, `beat` y `migrate` todavía no pueden arrancar: faltan `cli.py` (T026), la app

    `up -d --wait db redis proxy`.
  - **No** crees `main.py`, `worker.py` ni `cli.py` provisionales para que pase: los entregan sus
    tareas.
- **T007 completa** (incluidos `test_servicios_healthy_y_migrate_exitoso` y `test_flujo_de_ci`) se
